# FrictionLab — UX/UI Spec and v0 Prompt

## Visual direction

Style: **Vercel + Linear + research lab**.

- Premium dark mode.
- Clean typography.
- Subtle borders.
- Glassy cards.
- Soft gradients only where useful.
- Motion-ready states.
- Agent represented by workflow, tool calls, persona timelines and evidence.
- No generic chatbot UI.

## Main screens

### 1. App intro / audit setup

Layout:

- Hero: “Send a synthetic user swarm through your landing page.”
- Subtitle: “Paste a URL, define your audience, and FrictionLab runs evidence-backed synthetic UX sessions.”
- Big URL input.
- Fields: target audience, conversion goal, business type, market/language, brand tone, persona count.
- Right card: Audit blueprint.
- CTA: “Run synthetic audit”.
- Secondary: “Load demo audit”.

### 2. Live swarm dashboard

Layout:

```txt
Top: Workflow timeline
Left: Snapshot/evidence map
Center: Persona swarm grid
Right: Live event feed
Bottom: Emerging findings
```

States:

- Page extracted.
- Screenshots captured / fallback.
- Personas generated.
- Sessions running.
- Findings aggregated.
- Report generated.
- Presenter report generated.

### 3. Persona session detail

- Persona profile.
- Final verdict.
- Timeline events.
- Scores: hero clarity, offer understanding, trust, pricing clarity, CTA readiness.
- Evidence quotes.
- Objections and missing information.

### 4. Findings dashboard

- Conversion score ring.
- Friction map.
- Top 5 blockers.
- Severity badges.
- Affected personas.
- Evidence drawer.
- Impact/effort matrix.

### 5. Final report

- Executive summary.
- Conversion score.
- Persona outcomes table.
- Top blockers.
- Recommendations.
- Before/after hero.
- CTA variants.
- FAQ suggestions.
- Implementation checklist.
- Share button.

### 6. Copy Lab

- Hero rewrite cards: Conservative, Bold, Founder-friendly.
- CTA variants.
- Trust section copy.
- FAQ suggestions.

### 7. Presenter Report

- 45–60s client-friendly script.
- Storyboard cards.
- Scene timeline.
- Captions.
- Preview deck.
- Optional video render status.
- If video disabled/failed: “Storyboard ready — video render disabled.”

### 8. Shareable report

- Clean client-ready page.
- Report + presenter tabs.
- Minimal app chrome.
- “Generated by FrictionLab”.

## v0 prompt

Paste this into v0:

```txt
Build a premium dark-mode Next.js App Router UI for a product called FrictionLab.

FrictionLab is an AI conversion research agent that sends a synthetic user swarm through a landing page before real users bounce.

Use Tailwind and shadcn/ui. Style direction: Vercel + Linear + research lab. Premium, minimal, dark, sharp typography, subtle borders, glassy cards, soft motion-ready states. Do NOT make it look like a chatbot. It should feel like an AI research command center.

Create the following screens with realistic mock data and working navigation:

1. App intro / audit setup screen
- Large hero: “Send a synthetic user swarm through your landing page.”
- Subtitle: “Paste a URL, define your audience, and FrictionLab runs evidence-backed synthetic UX sessions.”
- Form fields:
  - Landing page URL
  - Target audience
  - Conversion goal
  - Business type select: SaaS, Agency, Ecommerce, Devtool, Fintech
  - Language / market
  - Brand tone
  - Number of synthetic users
- Right-side “Audit blueprint” card showing:
  - Capture page snapshot
  - Generate personas
  - Run synthetic sessions
  - Aggregate findings
  - Generate report
  - Generate presenter summary
- Primary CTA: “Run synthetic audit”
- Secondary CTA: “Load demo audit”

2. Live Swarm Dashboard
- Top workflow progress bar with steps:
  Page extracted, Screenshots captured, Personas generated, Sessions running, Findings aggregated, Report generated, Presenter generated
- Left panel: Page Snapshot Viewer with desktop/mobile tabs. Use a realistic placeholder screenshot card for a SaaS landing page.
- Center panel: Synthetic user swarm grid with 4 persona cards:
  Maya Chen — busy founder — mobile — hesitant
  Diego Alvarez — technical evaluator — desktop — investigating
  Priya Shah — price-sensitive buyer — desktop — skeptical
  Amara Okafor — trust-first operator — mobile — ready
- Each persona card should show current step, mini score, device, trust sensitivity, price sensitivity and verdict badge.
- Right panel: Live event feed with timestamped agent events.
- Bottom: Emerging findings cards with severity badges.

3. Persona Session Detail
- Header with persona profile and final verdict.
- Timeline of session events:
  Arrival, Hero scan, Offer evaluation, Trust check, CTA decision.
- Each event includes:
  - persona thought
  - evidence quote
  - friction point
  - decision: continue / hesitate / bounce / convert
- Score cards:
  Hero clarity, Offer understanding, Trust, Pricing clarity, CTA readiness.

4. Findings Dashboard
- Conversion score ring, e.g. 64/100.
- Friction map with stages:
  First impression, Understanding, Trust, Pricing, CTA.
- Top 5 blockers with:
  problem, evidence, affected personas, severity, suggested fix.
- Impact/effort matrix.
- Filters by category: Hero, Trust, CTA, Pricing, Mobile, Copy.

5. Final Report
- Client-ready report layout.
- Executive summary.
- Conversion score.
- Persona outcomes table.
- Top blockers.
- Recommendations with priority, impact, effort.
- Before/after hero rewrite.
- CTA variants.
- FAQ suggestions.
- Implementation checklist.
- Share button.

6. Copy Lab
- Hero rewrite cards:
  Conservative, Bold, Founder-friendly.
- CTA variants.
- Trust section copy.
- FAQ suggestions.

7. Presenter Report
- A premium storyboard/deck generated from the audit.
- Header: “Presenter Report: 60-second client brief.”
- Show 6 scene cards:
  Intro, Conversion Score, Persona Reactions, Top Friction, Recommended Fixes, Before/After Hero.
- Each scene card includes:
  - title
  - duration
  - narration
  - visual type
  - caption
- Include a “Voiceover script” panel.
- Include a “Video render” card with states:
  Not requested, Rendering, Ready, Failed, Disabled.
- Make storyboard/deck work even when video render is disabled.

8. Shareable Report Page
- Clean report-only layout, suitable for sending to a client.
- Include tabs: Report, Copy Lab, Presenter.
- Include “Generated by FrictionLab” branding.
- No app chrome except a simple top bar.

Component requirements:
- Use reusable components:
  WorkflowTimeline, PersonaCard, SwarmDashboard, SnapshotViewer, EvidenceDrawer, FindingCard, ScoreRing, ImpactEffortMatrix, ReportSection, CopyVariantCard, PresenterReport, PresenterStoryboard, SceneCard, VideoPreview, RenderStatus.
- Include mock data in a separate file.
- Make all screens responsive.
- Use polished empty/loading/error states.
- Include a demo mode banner: “Screenshot failed, continuing with DOM evidence.”
- Avoid generic chatbot UI. The agent should be represented through workflow steps, tool calls, personas, timelines, evidence and presenter scenes.

Interactions:
- Clicking “Run synthetic audit” navigates to the live dashboard using mock data.
- Clicking “Load demo audit” opens a completed demo audit.
- Clicking a persona opens the persona session detail.
- Clicking a finding opens an evidence drawer.
- Clicking “View report” opens the final report.
- Clicking “Presenter” opens the Presenter Report storyboard.
- Clicking “Share report” opens the shareable report page.

Use realistic content for a fictional B2B SaaS landing page called LaunchPilot.
```
